# Production dependencies. Exact pins, deliberately.
#
# This file is what Render and Railway install, both on Python 3.12 (see
# runtime.txt, nixpacks.toml and PYTHON_VERSION in render.yaml). Every pin below
# resolves to a wheel on 3.12, so nothing here needs a compiler at deploy time.
#
# Two pins are load-bearing beyond ordinary version hygiene:
#
#   starlette  Pinned explicitly, not left to fastapi's dependency range. On
#              starlette 1.x the commit in get_db()'s teardown lands *after* the
#              response is sent, so a client issuing its next request immediately
#              reads pre-commit state. That silently breaks the screen state
#              machine and the thesis/model guards, and it fails intermittently
#              rather than loudly. Verified against 1.3.1 vs 0.41.3.
#
#   pydantic   fastapi 0.115.6 accepts pydantic <3, so a floor like `>=2.10.4`
#              would install pydantic 3.x the day it ships and break a routine
#              redeploy with no change on your side. Same argument for sqlalchemy
#              and numpy.
#
# Developing on Python 3.14? pydantic-core, numpy, asyncpg and greenlet have no
# cp314 wheel at these versions and building them needs a C compiler plus a Rust
# toolchain. Use requirements-py314.txt locally instead. Do not relax this file
# to make a local install work -- production reproducibility is the thing it
# exists to protect.
